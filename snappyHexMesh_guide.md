# snappyHexMesh — Commands and Configuration Guide

**Introduction to OpenFOAM Workshop**  
**Distribution:** OpenFOAM OpenCFD / openfoam.com  
**Target environment:** Ubuntu, OpenFOAM v2412 installed with Conda (`cfd`)  
**Level:** Beginner to intermediate

This guide provides a practical reference for **terminal commands**, **command-line options**, **case files**, and the most useful **`snappyHexMeshDict` settings**. It is designed to be copied into a workshop repository as a README.

> **Important:** The terminal commands below assume you are working inside an existing, properly configured OpenFOAM case. The dictionary fragments are examples to adapt—not complete, standalone `snappyHexMeshDict` files. Geometry names, refinement levels, and locations must match your case. For the exact options supported by your installed build, run `snappyHexMesh -help-full`.

---

## 1. What does `snappyHexMesh` do?

`snappyHexMesh` generates a predominantly hexahedral mesh around or inside complex geometry. Its principal stages are:

1. **Background mesh** — create a pure-hexahedral base mesh, typically using `blockMesh`.
2. **Castellation** — refine cells near features, surfaces, and specified regions; retain the selected fluid region.
3. **Snapping** — move mesh vertices to conform to the target geometry.
4. **Layer addition** — optionally introduce prism-like cells adjacent to walls.
5. **Quality checking** — test and improve the mesh against specified criteria.

Conceptually:

```text
Background mesh (blockMesh) + Surface geometry (STL/OBJ)
                       |
                       v
                 Feature extraction
                       |
                       v
               Castellated refinement
                       |
                       v
                   Snapping
                       |
                       v
             Boundary layers (optional)
                       |
                       v
               checkMesh / ParaView
```

## 3. Required case files and directories

Typical layout:

```text
myCase/
├── 0/
│   ├── U                      # Velocity initial/boundary conditions (when solving)
│   └── p                      # Pressure initial/boundary conditions (when solving)
├── constant/
│   ├── triSurface/
│   │   ├── model.stl          # Input geometry
│   │   └── model.eMesh        # Feature edges generated by surfaceFeatureExtract
│   └── polyMesh/              # Background/final mesh generated by OpenFOAM
└── system/
    ├── blockMeshDict         # Background hexahedral mesh
    ├── surfaceFeatureExtractDict  # Optional feature-edge extraction
    ├── snappyHexMeshDict     # Controls snappyHexMesh
    ├── meshQualityDict       # Optional separate quality constraints
    ├── controlDict           # Run/output configuration
    └── decomposeParDict      # Needed for parallel meshing
```

`model.stl` is a placeholder. Replace it consistently everywhere with your actual STL filename. The named tutorial directories in the supplied teaching slides (`M101_wolf`, `M1cyl/C1`–`C4`, and `M3_ahmed`) are **separate supplied cases**, not guaranteed to be present in a standard OpenFOAM installation.

> **Units:** OpenFOAM uses SI units by convention. STL coordinates must have the intended physical scale; STL files do not reliably encode units.

## 4. Complete serial meshing workflow

Run these commands **from the root of your case directory**.

### 4.1 Inspect the geometry

```bash
ls constant/triSurface/
surfaceCheck constant/triSurface/model.stl
```

`surfaceCheck` identifies geometric/topological issues such as open edges and inconsistent surface characteristics. An open surface may be usable for some meshing workflows, but the intended retained region must be defined correctly.

### 4.2 Create and check the background mesh

```bash
blockMesh 2>&1 | tee log.blockMesh
checkMesh -constant 2>&1 | tee log.checkMesh.background
```

The background mesh should use hexahedral cells and adequately resolve the geometry. Near surfaces, avoid extreme cell aspect ratios.

### 4.3 Extract feature edges (when used)

```bash
surfaceFeatureExtract 2>&1 | tee log.surfaceFeatureExtract
ls constant/triSurface/*.eMesh
```

This requires a compatible `system/surfaceFeatureExtractDict`. Skip this step if your case does not use explicit feature-edge extraction.

### 4.4 Generate the final mesh

```bash
snappyHexMesh -overwrite 2>&1 | tee log.snappyHexMesh
```

The `-overwrite` option keeps the final mesh in `constant/polyMesh`, avoiding the intermediate mesh time directories normally written by each stage.

### 4.5 Inspect the final mesh

```bash
checkMesh -constant -allTopology -allGeometry 2>&1 | tee log.checkMesh.final
```

Read the results rather than relying only on the command's exit status. Pay particular attention to invalid cells, non-orthogonality, skewness, negative cell volumes, and disconnected regions.

### 4.6 Open in ParaView

```bash
touch case.foam
paraview case.foam
```

If `paraFoam` is installed and correctly configured, you can also try:

```bash
paraFoam
```

For Conda installations, opening an empty `.foam` file with the **native ParaView OpenFOAM reader** is often the simplest approach.

### Copy-and-paste summary

```bash
# From the case directory, after editing the required dictionaries:
blockMesh
surfaceCheck constant/triSurface/model.stl
surfaceFeatureExtract
snappyHexMesh -overwrite
checkMesh -constant -allTopology -allGeometry
touch case.foam
paraview case.foam
```

## 5. `snappyHexMesh` command-line options

These are the main OpenCFD command-line switches documented for the application. **Use `snappyHexMesh -help-full` to confirm the exact set on your installation.**

| Option | Meaning | Example |
|---|---|---|
| No option | Run all stages enabled in the dictionary and write intermediate meshes | `snappyHexMesh` |
| `-overwrite` | Overwrite mesh data rather than preserving each intermediate stage in time directories | `snappyHexMesh -overwrite` |
| `-case <dir>` | Work on a case other than the current directory | `snappyHexMesh -case ~/OpenFOAM/run/myCase` |
| `-dict <file>` | Use an alternative meshing dictionary | `snappyHexMesh -dict system/snappyHexMeshDict.test` |
| `-checkGeometry` | Check geometry inside the configured mesher | `snappyHexMesh -checkGeometry` |
| `-dry-run` | Check meshing setup without a full production mesh generation | `snappyHexMesh -dry-run` |
| `-parallel` | Enable parallel execution (with MPI) | `mpirun -np 4 snappyHexMesh -parallel -overwrite` |
| `-decomposeParDict <file>` | Use an alternative parallel decomposition dictionary | `snappyHexMesh -decomposeParDict system/decomposeParDict.test -parallel` |
| `-region <name>` | Mesh a named mesh region | `snappyHexMesh -region fluid -overwrite` |
| `-profiling` | Enable application-level profiling | `snappyHexMesh -profiling` |
| `-surfaceSimplify <boundBox>` | Advanced surface-simplification mode | See `snappyHexMesh -help-full` |
| `-outFile <file>` | Output path for the surface-simplification mode | See `snappyHexMesh -help-full` |
| `-patches <list>` | Select patches in advanced surface operations | See `snappyHexMesh -help-full` |
| `-doc` | Open the documentation in a browser (if available) | `snappyHexMesh -doc` |
| `-help` | Print help | `snappyHexMesh -help` |
| `-help-full` | Print extended help | `snappyHexMesh -help-full` |
| `-help-compat` | Show compatibility options, where supported | `snappyHexMesh -help-compat` |

Options such as `-surfaceSimplify`, `-outFile`, and `-patches` are **specialist functions**; they are not needed for a normal STL-to-mesh workshop exercise.

## 6. Understanding `system/snappyHexMeshDict`

The major sections and switches are:

```cpp
castellatedMesh true;   // Enable castellated cell refinement
snap            true;   // Snap mesh to the target geometry
addLayers       false;  // Disable wall layers for a first run

geometry
{
    // STL surfaces and/or analytic refinement objects
}

castellatedMeshControls
{
    // Feature, surface and region refinement; retained mesh location
}

snapControls
{
    // Surface and feature snapping
}

addLayersControls
{
    // Wall-layer generation
}

meshQualityControls
{
    // Mesh-quality constraints
}

mergeTolerance 1e-6;
```

**Important:** This is a **structural illustration**, not a complete executable dictionary. Start from a working OpenCFD tutorial and modify its values.

### Enable or disable individual stages

| Desired result | `castellatedMesh` | `snap` | `addLayers` |
|---|---|---|---|
| Castellated mesh only | `true` | `false` | `false` |
| Body-fitted mesh, no layers | `true` | `true` | `false` |
| Body-fitted mesh with wall layers | `true` | `true` | `true` |

## 7. Geometry: `geometry`

A typical STL definition:

```cpp
geometry
{
    model.stl
    {
        type triSurfaceMesh;
        name obstacle;
    }

    refinementBox
    {
        type searchableBox;
        min (-0.5 -0.5 -0.5);
        max ( 0.5  0.5  0.5);
    }
}
```

- `model.stl` is read from `constant/triSurface/`.
- `obstacle` is the name subsequently used in `refinementSurfaces`.
- `refinementBox` is an example of an analytical volume used for local refinement.
- Other geometry types include spheres, cylinders, and additional STL files.

To inspect the STL using ParaView:

```bash
paraview constant/triSurface/model.stl
```

### Optional: split an STL into multiple surface regions

The supplied training material demonstrates `surfaceAutoPatch`:

```bash
surfaceAutoPatch geo.stl output.stl 130
```

The last number is an angle criterion. Review the result before using it, especially around sharp features. This is not a mandatory step.

## 8. Explicit feature edges: `surfaceFeatureExtract`

**Terminal command:**

```bash
surfaceFeatureExtract
```

Example `system/surfaceFeatureExtractDict`:

```cpp
model.stl
{
    extractionMethod extractFromSurface;

    extractFromSurfaceCoeffs
    {
        includedAngle 150;
    }

    subsetFeatures
    {
        nonManifoldEdges yes;
        openEdges        yes;
    }

    writeObj yes;
}
```

An `.eMesh` file is then produced for feature refinement (in the geometry directory in the standard workflow).

Reference the extracted edges in `castellatedMeshControls`:

```cpp
features
(
    {
        file "model.eMesh";
        level 2;
    }
);
```

**Important:** `includedAngle` controls feature extraction; `resolveFeatureAngle` below controls additional surface refinement. They are not interchangeable.

## 9. Castellation: `castellatedMeshControls`

Illustrative settings:

```cpp
castellatedMeshControls
{
    maxLocalCells       100000;
    maxGlobalCells      2000000;
    minRefinementCells  0;
    maxLoadUnbalance    0.10;
    nCellsBetweenLevels 2;
    resolveFeatureAngle 30;

    features
    (
        {
            file "model.eMesh";
            level 2;
        }
    );

    refinementSurfaces
    {
        obstacle
        {
            level (2 3);
            patchInfo
            {
                type wall;
            }
        }
    }

    refinementRegions
    {
        refinementBox
        {
            mode inside;
            levels ((1e15 2));
        }
    }

    locationInMesh (0.8 0.8 0.8);
    allowFreeStandingZoneFaces true;
}
```

**Adapt the values.** The example `locationInMesh` must be placed **inside the desired fluid region and inside the background mesh, but not on a surface**. For external flow it is typically outside the solid obstacle; for internal flow it is within the enclosed fluid volume.

| Keyword | Meaning |
|---|---|
| `maxLocalCells` | Target limit used to trigger parallel redistribution |
| `maxGlobalCells` | Maximum global cell count for refinement control |
| `minRefinementCells` | Threshold used to terminate refinement |
| `nCellsBetweenLevels` | Width of transitions between refinement levels |
| `resolveFeatureAngle` | Surface feature-angle criterion for refinement |
| `features` | Explicit edge-mesh refinements (`.eMesh`) |
| `refinementSurfaces` | Cell refinement at geometric surfaces |
| `refinementRegions` | Extra refinement in selected volumes or near surfaces |
| `locationInMesh` | Selects which connected region of cells to retain |

### Surface refinement levels

```cpp
refinementSurfaces
{
    obstacle
    {
        level (2 4);
    }
}
```

The first value is the minimum surface refinement level; the second is the maximum allowed at features/curvature according to the relevant criteria.

Each additional level approximately halves the cell width in each spatial direction. Thus, a fully refined 3D hexahedral cell can split into **eight** smaller cells per level.

### Distance-based refinement

```cpp
refinementRegions
{
    obstacle
    {
        mode distance;
        levels
        (
            (0.05 3)
            (0.15 2)
        );
    }
}
```

This refines to level 3 close to the surface (within 0.05 case length units) and to level 2 farther away (within 0.15 units). Distances must be meaningful for your geometry.

## 10. Snapping: `snapControls`

```cpp
snapControls
{
    nSmoothPatch           3;
    tolerance              2.0;
    nSolveIter             30;
    nRelaxIter             5;

    nFeatureSnapIter       10;
    implicitFeatureSnap    false;
    explicitFeatureSnap    true;
    multiRegionFeatureSnap false;
}
```

| Keyword | Meaning |
|---|---|
| `nSmoothPatch` | Patch smoothing iterations before snapping |
| `tolerance` | Attraction distance relative to local cell size |
| `nSolveIter` | Mesh displacement solution iterations |
| `nRelaxIter` | Relaxation iterations |
| `nFeatureSnapIter` | Iterations for capturing sharp feature lines |
| `implicitFeatureSnap` | Detect features from the geometry |
| `explicitFeatureSnap` | Use the `.eMesh` feature lines |
| `multiRegionFeatureSnap` | Capture features at multi-region intersections |

Start with reasonable tutorial defaults. Change parameters one at a time if the mesh does not conform to the geometry.

## 11. Boundary layers: `addLayersControls`

Set the top-level option:

```cpp
addLayers true;
```

Then configure, for example:

```cpp
addLayersControls
{
    relativeSizes        true;
    expansionRatio       1.2;
    finalLayerThickness  0.3;
    minThickness         0.1;

    layers
    {
        obstacle
        {
            nSurfaceLayers 3;
        }
    }

    nGrow                 0;
    featureAngle          130;
    nSmoothSurfaceNormals 1;
    nSmoothThickness      10;
    nLayerIter            50;
    nRelaxedIter          20;
}
```

| Keyword | Meaning |
|---|---|
| `relativeSizes` | `true`: sizing relative to local mesh; `false`: absolute thicknesses |
| `nSurfaceLayers` | Requested number of layers on a named boundary patch |
| `expansionRatio` | Thickness growth factor between successive layers |
| `firstLayerThickness` | Desired first layer thickness, when selected as the sizing method |
| `finalLayerThickness` | Desired outermost layer thickness, when selected as the sizing method |
| `minThickness` | Minimum acceptable total thickness for layer insertion |
| `featureAngle` | Controls layer extrusion near sharp changes in surface direction |
| `nGrow` | Number of cells near features where extrusion is suppressed |
| `nLayerIter` | Maximum layer-generation iterations |

**Practical advice:** First obtain a valid **castellated + snapped mesh without layers**. Only then enable layers. Successful layer addition is not guaranteed merely by setting `nSurfaceLayers` to a positive number. Inspect the layer-coverage statistics in the log and the layers in ParaView.

If precise near-wall resolution is required (e.g. for turbulence modelling), design the first-layer thickness based on the target **y+** and check it after obtaining a flow solution.

## 12. Quality controls: `meshQualityControls`

Many tutorials keep quality limits in a separate file:

```cpp
meshQualityControls
{
    #include "meshQualityDict"
}
```

The case must actually contain `system/meshQualityDict` for this include to work.

Common controls include:

| Parameter | What it constrains |
|---|---|
| `maxNonOrtho` | Maximum face non-orthogonality |
| `maxBoundarySkewness` | Skewness of boundary faces |
| `maxInternalSkewness` | Skewness of internal faces |
| `maxConcave` | Allowed face concavity |
| `minVol` | Minimum cell volume |
| `minDeterminant` | Cell quality determinant |
| `minFaceWeight` | Minimum interpolation weight |
| `minVolRatio` | Minimum cell-volume ratio |
| `errorReduction` | Reduction of problematic displacement steps |

Do not copy arbitrary numeric quality thresholds between cases or OpenFOAM versions. Begin with a compatible tutorial and verify the result using:

```bash
checkMesh -constant -allTopology -allGeometry
```

## 13. Saving intermediate meshes vs `-overwrite`

### Option A — Final mesh only (recommended for beginners)

```bash
blockMesh
surfaceFeatureExtract
snappyHexMesh -overwrite
checkMesh -constant
```

- Output: final mesh in `constant/polyMesh`.
- Does not preserve every intermediate stage for later visualisation or restart.

### Option B — Save stage-by-stage meshes

```bash
blockMesh
surfaceFeatureExtract
snappyHexMesh
checkMesh -latestTime
```

- Castellation, snapping, and layer addition may be written into successive **time directories**.
- Inspect the generated directories before moving files. Their names are not guaranteed to be `1`, `2`, and `3` in every case.
- To use the final mesh as the constant mesh for a subsequent CFD simulation, copy the final `<time>/polyMesh/` contents into `constant/polyMesh/` **after checking which directory contains the desired mesh**.

Example, **only if** the final mesh was written to directory `3`:

```bash
cp -a 3/polyMesh/. constant/polyMesh/
checkMesh -constant
```

Avoid deleting the original or intermediate mesh directories until the final mesh is validated. Prefer working on copies of tutorial cases.

### Restarting only the layer stage (advanced)

If intermediate meshes were saved, you can restart from a snapped-mesh time directory by adjusting `system/controlDict` to start from that time and setting:

```cpp
castellatedMesh false;
snap            false;
addLayers       true;
```

Then run:

```bash
snappyHexMesh
```

This requires that the selected start time actually contains the saved **snapped mesh**; it is not a universal one-command restart.

## 14. Running `snappyHexMesh` in parallel (advanced)

Use parallel meshing for larger cases **only if MPI is available and compatible with the installed OpenFOAM build**.

### 14.1 Configure decomposition

Example `system/decomposeParDict`:

```cpp
numberOfSubdomains 4;
method scotch;
```

### 14.2 Run the mesh generation

```bash
which mpirun
blockMesh
surfaceFeatureExtract
decomposePar -force
mpirun -np 4 snappyHexMesh -parallel -overwrite 2>&1 | tee log.snappyHexMesh.parallel
```

### 14.3 Reconstruct and validate the mesh

```bash
reconstructParMesh -constant
checkMesh -constant -allTopology -allGeometry
```

**Note:** `reconstructParMesh` reconstructs the mesh. For a subsequent parallel **CFD simulation**, `reconstructPar` is used to reconstruct solution fields. The two utilities have different purposes.

## 15. Making a 2D case from a 3D mesh (advanced)

`snappyHexMesh` is a **3D mesher**. The training slides demonstrate meshing a thin 3D domain and subsequently using `extrudeMesh` to produce a single-cell-thick, effectively 2D mesh.

```bash
blockMesh
snappyHexMesh -overwrite
extrudeMesh
checkMesh -latestTime
```

`extrudeMesh` requires a properly configured `system/extrudeMeshDict`, and the out-of-plane boundaries must be set appropriately (typically `empty`) for a 2D solver. The precise dictionary depends on the geometry and mesh orientation.

## 16. Cleaning, inspecting and troubleshooting

### Inspect configuration files

```bash
cat system/snappyHexMeshDict
cat system/blockMeshDict
cat system/surfaceFeatureExtractDict
cat constant/polyMesh/boundary
```

If `foamDictionary` is available, selected settings can be queried:

```bash
foamDictionary system/snappyHexMeshDict -entry castellatedMesh -value
foamDictionary system/snappyHexMeshDict -entry snap -value
foamDictionary system/snappyHexMeshDict -entry addLayers -value
```

### Capture logs and watch progress

```bash
snappyHexMesh -overwrite > log.snappyHexMesh 2>&1
tail -n 50 log.snappyHexMesh
```

To monitor the log **while a separate process is running**:

```bash
tail -f log.snappyHexMesh
```

Use `Ctrl+C` to stop following the log without stopping a separately launched mesh job.

### Inspect final boundary patches

```bash
cat constant/polyMesh/boundary
```

The patch names in `constant/polyMesh/boundary` must match those referenced by the field boundary conditions in `0/U`, `0/p`, etc. after meshing.

### Mesh-quality diagnostics

```bash
checkMesh -constant
checkMesh -constant -allTopology -allGeometry
```

### Common problems

| Problem | First thing to check |
|---|---|
| `snappyHexMesh: command not found` | `conda activate cfd`, `which snappyHexMesh` |
| STL cannot be opened | Filename/path in `geometry`; `constant/triSurface/` |
| `model.eMesh` is missing | Run `surfaceFeatureExtract` with a matching dictionary |
| Wrong cells retained | `locationInMesh` point and watertightness/connectivity |
| Geometry not captured | Base cell size, refinement levels, feature snapping |
| Excessive cell count | `maxGlobalCells`, surface/region refinement levels |
| Boundary layers missing | `addLayers`, `layers` patch names, thickness and mesh quality |
| High non-orthogonality/skewness | Background grid, refinement transitions, snapping settings |
| ParaView reader problem | `touch case.foam` then `paraview case.foam` |

**Cleaning caution:** The supplied slides mention `foamCleanTutorials` and `foamCleanPolyMesh`. These may depend on the particular OpenFOAM installation, and cleaning can remove data. **Do not run a cleanup command inside a case you need to preserve.** Create and work with a copy first.
